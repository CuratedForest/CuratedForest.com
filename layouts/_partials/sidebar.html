{{/* sidebar.html (site override) Forked from the compose theme's layouts/_partials/sidebar.html. Two behavioral changes vs upstream: 1. Tree root: the theme renders the sidebar starting at .FirstSection (the top-level section of the current page), so the tree shifts up a level as you navigate into a subsection and the depth-based CSS in _custom.sass renders the same logical entry at different sizes on different pages. Here we always root the tree at site.Home so every page sees the identical tree (same depths, sizes, indentation, and collapsed-state heuristics in custom.js). 2. Section vs page branch: the upstream loop branched on `.IsPage`, which causes a folder whose only file is an `_index.md` (no other child pages) to render as a small `

` instead of a `

` header — making it look visually subordinate to siblings like Home Assistant or Kubernetes that happen to have child pages. We branch on `.IsSection` instead so every section in the tree — even one with no children yet — renders with the same `section_title` styling. Regular page files (e.g. a stray `tech/foo.md`) still fall through to the `section_link` rendering. */}}
